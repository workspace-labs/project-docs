# البيانات: حجز عيادة سيدر
> الإصدار 5 · مسودة

## ما يحفظه
من هم المرضى، وأي الأطباء يستقبلون المواعيد، وكل موعد، والموظفون الذين يستخدمون قائمة الاستقبال.
الجداول: المرضى · الأطباء · المواعيد · الموظفون · أحداث التدقيق (قاعدة الأمان).
- **إذا ضاعت هذه النسخة:** يمكن قراءة النسخة الليلية التي يأخذها مسؤول تقنية المعلومات على القرص الثاني في العيادة؛ وقد تضيع مواعيد يوم واحد كحد أقصى.
  - تغيّر في 2026-11-21: من لا سطر إلى النسخة الليلية مع احتمال ضياع مواعيد يوم واحد، لأن الإصدار 4 كُتب قبل طلب هذا السطر.

## الجداول

### المرضى (patients)
الصف الواحد هو مريض واحد من مرضى العيادة.

| العمود | يحمل | مثال | العلامة |
|---|---|---|---|
| id | رقم يعطيه النظام | 1042 | – |
| full_name | اسم المريض | سارة مثال | 🔒 شخصي |
| phone | حيث تصل رسائل التذكير ورموز الدخول | +000 5550 1234 | 🔒 شخصي |
| sign_in_code_hash | نسخة مشفّرة من آخر رمز دخول | (مشفّر) | 🔐 سري |
| created_at | متى حجز المريض أول مرة | 2026-10-14 09:12 | – |

- **من يستطيع رؤيته:** يرى موظفو الاستقبال كل المرضى، ويرى المريض صفه فقط.
- **مدة الاحتفاظ به:** سنتان بعد آخر موعد للمريض، أو أقل إذا طلب المريض حذفه.
- **مطلوب:** `id` (مولّد)، `full_name`، `phone`، `created_at` (له قيمة تلقائية). قد لا توجد تجزئة الرمز.
- **فريد:** `id`، `phone`.
- **الحذف:** يتحقق الاستقبال من طلب المريض، ثم يحذف مواعيده (وأحداث التدقيق المرتبطة) قبل حذف المريض. تستخدم إزالة السجلات المنتهية الترتيب نفسه عند انتهاء السنتين.

### الأطباء (doctors)
الصف الواحد هو طبيب واحد يستقبل المواعيد.

| العمود | يحمل | مثال | العلامة |
|---|---|---|---|
| id | رقم يعطيه النظام | 3 | – |
| display_name | الاسم الذي يراه المرضى | د. حدّاد | 🔒 شخصي |
| speciality | نوع الطبيب | طبيب عائلة | – |
| visit_minutes | مدة الموعد الواحد بالدقائق | 20 | – |

- **من يستطيع رؤيته:** الجميع، حتى المرضى الذين لم يسجّلوا الدخول: الأسماء معروضة عن قصد ليختار المرضى طبيبهم.
- **مدة الاحتفاظ به:** ما دام الطبيب يعمل في العيادة، ثم حتى تُحذف مواعيده المرتبطة.
- **مطلوب:** `id` (مولّد)، `display_name`، `speciality`، `visit_minutes`.
- **فريد:** `id`.
- **الحذف:** يحذف مسؤول تقنية المعلومات صف الطبيب المغادر بعد حذف مواعيده المرتبطة؛ لا يجوز أن يشير موعد إلى طبيب غير موجود.

### المواعيد (visits)
الصف الواحد هو موعد محجوز: من، ومع أي طبيب، ومتى.

| العمود | يحمل | مثال | العلامة |
|---|---|---|---|
| id | رقم يعطيه النظام | 88213 | – |
| patient_id | أي مريض | 1042 | 🔒 شخصي |
| doctor_id | أي طبيب | 3 | 🔒 شخصي |
| starts_at | اليوم والساعة | 2026-10-14 09:30 | – |
| status | محجوز أو مُغيَّر أو ملغى | booked | – |
| reminder_sent_at | متى أُرسل التذكير | 2026-10-13 18:00 | – |

- **من يستطيع رؤيته:** يرى موظفو الاستقبال كل المواعيد، ويرى المريض مواعيده فقط.
- **مدة الاحتفاظ به:** سنتان، ثم يُحذف.
- **مطلوب:** `id` (مولّد)، `patient_id`، `doctor_id`، `starts_at`، `status`. قد لا يوجد وقت إرسال التذكير.
- **فريد:** `id`. القيد المركّب: لا تتكرر `doctor_id` + `starts_at` إلا إذا كان الموعد ملغى.
- **الحذف:** يتولى الاستقبال طلب حذف المريض بعد التحقق منه؛ وتزيل عملية انتهاء مدة الحفظ المواعيد المنتهية. حذف الموعد يحذف أحداث تدقيقه أيضًا.

### الموظفون (staff)
الصف الواحد هو موظف استقبال واحد، من دخول Microsoft 365 الخاص بالعيادة.
  - تغيّر في 2026-10-19: من موظف دون معرّف حساب Microsoft محفوظ إلى موظف بمعرّف حساب Microsoft محفوظ، لأن الأمان يتطلب هوية ثابتة من مزوّد الدخول.

| العمود | يحمل | مثال | العلامة |
|---|---|---|---|
| id | رقم يعطيه النظام | 7 | – |
| microsoft_account_id | معرّف الحساب الثابت من دخول Microsoft الخاص بالعيادة بعد التحقق منه، وليس البريد | clinic-account-007 | 🔒 شخصي |
| work_email | بريده في العيادة، من الدخول | desk@clinic.example | 🔒 شخصي |
| display_name | اسمه | استقبال 1 | 🔒 شخصي |

- **من يستطيع رؤيته:** مسؤول تقنية المعلومات في العيادة فقط.
- **مدة الاحتفاظ به:** حتى يغادر الموظف العيادة.
- **مطلوب:** `id` (مولّد)، `microsoft_account_id`، `work_email`، `display_name`.
- **فريد:** `id`، `microsoft_account_id`، `work_email`.
- **الحذف:** يحذف مسؤول تقنية المعلومات صف الموظف عند مغادرته، وتُحذف أحداث تدقيقه المرتبطة أيضًا.

### أحداث التدقيق (audit_events)
الصف الواحد هو محاولة موظف فتح موعد مريض محمي أو تغييره أو إلغائه، بحسب قاعدة الأمان.

| العمود | يحمل | مثال | العلامة |
|---|---|---|---|
| id | رقم يعطيه النظام | 18 | – |
| actor_id | أي موظف قام بالفعل | 7 | 🔒 شخصي |
| visit_id | أي موعد محمي شمله الفعل | 88213 | 🔒 شخصي |
| event_at | متى حدث | 2026-10-14 09:32 | – |
| action | فتح أو تغيير أو إلغاء | open | – |
| outcome | نجاح أو رفض | success | – |

- **من يستطيع رؤيته:** مسؤول تقنية المعلومات في العيادة فقط. لا تُنسخ هنا قيم المرضى أو الرموز أو المفاتيح.
- **مدة الاحتفاظ به:** 90 يومًا كحد أقصى، أو أقل إذا حُذف الموعد أو الموظف المرتبط.
- **مطلوب:** `id` (مولّد)، `actor_id`، `visit_id`، `event_at` (له قيمة تلقائية)، `action`، `outcome`.
- **فريد:** `id`.
- **الحذف:** تزيل عملية انتهاء مدة الحفظ التي ينفّذها مسؤول تقنية المعلومات الأحداث الأقدم من 90 يومًا؛ وحذف الموعد أو الموظف المرتبط يحذفها أيضًا.

## كيف ترتبط الجداول
- كل موعد يخص مريضًا واحدًا وطبيبًا واحدًا.
- للطبيب موعد واحد في كل وقت: لا يمكن أن يبدأ موعدان غير ملغيين مع الطبيب نفسه في الوقت نفسه.
- تُحذف مواعيد المريض قبل المريض، ومواعيد الطبيب المغادر قبل الطبيب. يشير كل حدث تدقيق إلى موظف وموعد؛ وحذف أيهما يحذف الحدث.

## الكود الجاهز
```sql
-- PostgreSQL (محسوم في TRD)
CREATE TABLE patients (
  id                bigserial PRIMARY KEY,
  full_name         text NOT NULL,          -- شخصي
  phone             text NOT NULL UNIQUE,   -- شخصي
  sign_in_code_hash text,                   -- سري: نسخة مشفّرة فقط، لا الرمز نفسه
  created_at        timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE doctors (
  id            bigserial PRIMARY KEY,
  display_name  text NOT NULL,          -- شخصي (معروض عن قصد)
  speciality    text NOT NULL,
  visit_minutes integer NOT NULL CHECK (visit_minutes > 0)
);

CREATE TABLE visits (
  id               bigserial PRIMARY KEY,
  patient_id       bigint NOT NULL REFERENCES patients(id),   -- شخصي
  doctor_id        bigint NOT NULL REFERENCES doctors(id),    -- شخصي
  starts_at        timestamptz NOT NULL,
  status           text NOT NULL CHECK (status IN ('booked', 'moved', 'cancelled')),
  reminder_sent_at timestamptz
);
-- لا موعدين محجوزين مع الطبيب نفسه في الوقت نفسه.
CREATE UNIQUE INDEX one_visit_per_doctor_time ON visits (doctor_id, starts_at) WHERE status <> 'cancelled';

CREATE TABLE staff (
  id           bigserial PRIMARY KEY,
  microsoft_account_id text NOT NULL UNIQUE, -- شخصي: هوية Microsoft الثابتة، وليست البريد
  work_email   text NOT NULL UNIQUE,        -- شخصي
  display_name text NOT NULL                -- شخصي
);

CREATE TABLE audit_events (
  id       bigserial PRIMARY KEY,
  actor_id bigint NOT NULL REFERENCES staff(id) ON DELETE CASCADE,
  visit_id bigint NOT NULL REFERENCES visits(id) ON DELETE CASCADE,
  event_at timestamptz NOT NULL DEFAULT now(),
  action   text NOT NULL CHECK (action IN ('open', 'move', 'cancel')),
  outcome  text NOT NULL CHECK (outcome IN ('success', 'refused'))
);
```
